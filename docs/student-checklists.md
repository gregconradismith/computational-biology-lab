# Student Checklists

Use these checklists to make research work easier to restart, review, and hand off.

## Starting A New Example

- Read the nearest `README.md`.
- Identify the first file to run or compile.
- Confirm required software, packages, kernel, or cluster environment.
- Run the example unchanged before editing it.
- Save the command you used and the output you expected.

## Before A Lab Meeting

- Write the date and project name at the top of your notes.
- List the files, scripts, notebooks, or documents you touched.
- Record parameter values and commands.
- Include plots, error messages, or numerical output that changed your thinking.
- Write one question and one proposed next step.

## Before Sharing Work

- Remove private data, credentials, and local absolute paths.
- Keep generated files only when they help someone understand or reproduce the result.
- Add a short note explaining what changed and how to check it.
- Prefer links to official sources instead of downloaded third-party PDFs.
- Ask whether unpublished results or student-specific material belongs in the private repository.

## Good First README Improvement

If a folder is confusing, add or propose a short `README.md` with:

1. what the example teaches
2. required software or packages
3. what to run first
4. expected output
5. where to look next
